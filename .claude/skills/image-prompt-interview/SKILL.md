# 이미지 생성 프롬프트 인터뷰

사용자가 말한 장면을 **여섯 칸**으로 나눠 빈 칸만 되묻고, 60~120단어의 문장형 프롬프트로 조립한다. 어느 칸을 무엇으로 채웠는지 함께 밝혀, 이후 "한 번에 한 칸만" 고칠 수 있게 한다.

## 전제: 문장으로 쓴다
요즘 텍스트 인코더는 이미지 전용 인코더가 아니라 **현역 언어모델**이다. 쉼표로 끊은 명사 더미보다 "누가 어디서 무엇을 하고, 빛이 어디서 온다"는 문장을 더 잘 읽는다.
- `masterpiece, best quality, ultra detailed, 8k` 류는 지금 모델에서 대개 효과가 없거나 그림을 어중간하게 만든다. **쓰지 않는다.** 그 자리에 "무엇을 찍은 사진인가"를 적는다. (예: "다큐멘터리 사진, 얕은 심도")
- 사용자가 키워드 나열 프롬프트를 가져오면, 의도를 읽어 여섯 칸으로 재분류한 뒤 문장으로 다시 쓴다.

## 질문은 AskUserQuestion 도구로 한다
되묻기는 산문 질문 대신 **AskUserQuestion 도구**를 쓴다. (스키마가 로드돼 있지 않으면 먼저 ToolSearch로 `select:AskUserQuestion`을 불러온다.)
- 한 번 호출에 질문 **최대 4개**, 질문마다 선택지 2~4개. "기타" 입력은 도구가 자동 제공하므로 선택지에 넣지 않는다.
- 사용자가 이미 말한 항목은 묻지 않는다. 장면 설명 자체가 없으면 그것만 산문으로 한 번 묻는다(자유 서술이라 선택지가 안 맞는다).
- 선택지는 **장면에 맞게 구체적으로** 만든다(범용 문구 금지). 권장안이 있으면 첫 번째에 두고 라벨 끝에 "(Recommended)".
- 자유 서술이 필요한 칸(피사체의 구체적 모습 등)은 선택지 2~3개를 제안하고 "기타"로 직접 쓰게 한다.
- 답을 받은 뒤에도 빈 칸이 남으면 한 번 더 호출한다. 총 2회를 넘기지 않는다. 그래도 남은 칸은 기본값으로 채우고 (기본값) 표시.
- "알아서 해줘"를 고른 칸은 묻지 않고 (기본값)으로 채운다.

## 시작 전 확인 (3가지, 이미 말했으면 생략)
첫 AskUserQuestion 호출에 아래를 묶는다. 칸 질문과 합쳐 4개를 넘기지 않는다.
1. **용도**: 어디에 쓰는가 (썸네일, 슬라이드 삽화, 제품 목업 …) — 비율·여백·글자 자리 판단에 쓴다.
2. **매체**: 사진 / 일러스트 / 3D / 그 외.
3. **도구·모델**: 어떤 도구인가, 네거티브 프롬프트 칸이 있는가, 시드를 고정할 수 있는가. 모르면 "모름"으로 두고 네거티브는 비운다.

## 여섯 칸
순서는 "무엇이 있고 → 무엇을 하고 → 어떻게 담을지"다. 사람이 장면을 떠올리는 순서라 빠진 칸이 눈에 띈다. **사용자가 말하지 않은 칸만** 묻는다(AskUserQuestion, 위 규칙). 질문 하나에 칸 하나, 선택지는 그 칸의 구체 후보로 만든다.

| 칸 | 적을 것 | 요령 |
|---|---|---|
| 피사체 | 무엇이, 몇 명/개, 어떤 상태 | "사람"이 아니라 "안전모를 쓴 작업자 한 명". **수를 정한다** — 안 정하면 모델이 정하고 대개 더 많아진다 |
| 동작 | 무엇을 하고 **어디서 끝나는가**, 시선 | "일한다"보다 "라인 위로 몸을 숙여 한 손을 난간에 얹었다". 시선을 안 적으면 카메라를 본다 |
| 카메라 | 샷 크기 1 · 각도 1 · 렌즈 1 | **셋을 넘기지 않는다.** 넷째부터 서로 부딪힌다 |
| 조명 | 빛의 방향과 성질 | 창가의 부드러운 빛 / 형광등 / 역광. 안 적으면 밋밋한 정면광이 붙는다 |
| 환경 | 어디, 언제, 배경 요소 | |
| 스타일 | 사진/일러스트, 질감, 전체 결 | |

**선택 칸 — 재질과 표면**: 빛이 재질에서 어떻게 구는지 한 줄 (예: "잘 닦인 대리석 상판에 펜던트 조명이 반사되고, 피어오르는 김이 빛을 받아 결이 보인다"). 그림이 눈에 띄게 진짜 같아진다. 여섯 칸으로 이미 충분히 좁혀졌으면 넣지 않는다.

### 기본값으로 채우는 칸
사용자가 "알아서"라고 하거나 답이 없으면 합리적 기본값으로 채우되, 출력에서 **(기본값)** 으로 표시한다. 늘 같은 화풍을 쓰는 사용자라면 스타일 칸의 기본값을 아래에 박아 쓴다.
> 스타일 기본값(수정해서 사용): _(비워 둠 — 사용자 업무에 맞게 채울 것)_

## 조립 규칙
- **60~120단어.** 200단어 의식의 흐름보다 60단어 구조가 낫다. 길수록 모순된 지시가 섞인다.
- **긍정형으로 쓴다.** "사람이 없는 공장" ✕ → "텅 빈 공장" ○. 없애고 싶은 것이 아니라 **있었으면 하는 상태**를 말한다. 부정어에도 그 단어가 들어 있어 그쪽으로 끌린다.
- **모델이 배운 어휘를 쓴다.** 캡션에 자주 붙던 용어가 잘 통한다: 달리 인, 하이 앵글, 사이드 라이팅, 소프트박스, 얕은 심도.
- **요소를 욱여넣지 않는다.** 등장인물 다섯에 사건 셋이면 감당 못 한다. 프롬프트를 늘리지 말고 **장면을 나눈다** — 배경 → 인물 1 → 인물 2 순으로 층층이 쌓고, 만든 그림을 다시 넣어 고친다.
- 한국어로 설명했으면 **영어 프롬프트로 옮겨** 준다(한국어 원문도 함께). 도구가 한국어를 지원한다고 확인되면 그대로 둔다.

## 네거티브 프롬프트
- 기본은 **비운다.** `worst quality, bad anatomy, bad hands …` 같은 수십 개 덩어리는 효과가 증명된 적이 없다. 그런 태그 체계로 학습한 계열 모델에서만 통했고, 그 외에서는 "없는 개념을 지우라"는 셈이다.
- 작동 여부는 모델·실행 구현에 달렸다. 가이던스 0을 쓰는 SDXL-Turbo류는 네거티브를 쓰지 않는다. **증류판이라는 이름만으로 판단하지 말고** 도구의 지원 여부를 확인한다.
- 넣는다면 **짧게, 실제로 확인한 것만.** 안 될 때는 긍정형 프롬프트를 고치는 쪽이 거의 항상 더 효과적이다.

## 출력 형식
```
## 프롬프트 (영문, NN단어)
<문장형 프롬프트>

## 한국어 대응
<원문 의도를 한국어로>

## 칸별 채움
| 칸 | 내용 | 출처 |
| 피사체 | … | 사용자 |
| 동작 | … | 사용자 |
| 카메라 | … | (기본값) |
| 조명 | … | 사용자 |
| 환경 | … | 사용자 |
| 스타일 | … | (기본값) |
| 재질(선택) | … / 생략 | |

네거티브: 비움 | <내용 + 확인한 근거>
```
"출처" 열이 핵심이다: 기본값으로 채운 칸이 보여야 **한 번에 한 칸만** 바꿀 수 있다.

## 결과가 마음에 안 들 때 (고쳐 가는 법)
못 쓰는 방식은 통째로 다시 쓰기 → 단어 더하기 → 모델 바꾸기다. 무엇이 효과였는지 끝까지 모른다. 대신:
1. **시드를 고정**한다. 그래야 달라진 것이 프롬프트 때문이라고 말할 수 있다.
2. **한 번에 한 칸만** 바꾼다. 조명을 고쳤으면 조명만 본다.
3. **무엇을 바꿨는지 적어 둔다.** 서너 번만 돌아도 기억이 섞인다.
4. 여섯 칸을 다 채웠는데도 안 되면 그때 모델·도구를 의심한다.
5. 마음에 드는 결과가 나오면 **시드를 풀어 여러 장** 뽑는다. 같은 프롬프트의 다른 시드가 쓸 만한 한 장을 고르는 가장 빠른 길이다.

안 통할 때 원인은 둘 중 하나다: **안 적었거나, 적었는데 모델이 그 말을 모르거나.** 후자면 같은 뜻의 다른 용어로 바꿔 본다.

## 프롬프트로 안 되는 것 — 미리 알려 준다
요청 장면에 아래가 있으면 프롬프트를 쓰기 전에 **구도·작업 방식을 먼저 제안**한다.
- **손가락·손**: 잠재 공간에서 손이 차지하는 자리가 좁고, 각도별로 모양이 달라 학습 데이터에도 온전한 손이 적다. "손가락 다섯 개"라고 적어도 대개 소용없다. → 손이 크게 안 잡히는 구도, 또는 손이 잘 나온 그림을 먼저 확보해 거기서 출발. 물건을 쥔 손·맞잡은 두 손은 최신 모델에서도 잘 무너지니 처음부터 다른 구도를 권한다.
- **화면 안 글자**: 한글은 영어보다 어렵다. → 글자 자리를 **비워 두고** 나중에 편집 도구로 넣는다(가장 확실).
- **한 곳만 이상한 그림**: 프롬프트를 백 번 고치지 말고 **부분 재생성(인페인팅)** 을 쓴다.

## 하지 않는 것
- 사용자가 말하지 않은 칸을 말없이 채우지 않는다(채웠으면 반드시 (기본값) 표시).
- 칸을 채우려고 카메라 항목을 3개 넘게 넣지 않는다.
- "8k / masterpiece / ultra detailed", 수십 개짜리 네거티브 덩어리를 습관처럼 붙이지 않는다.
