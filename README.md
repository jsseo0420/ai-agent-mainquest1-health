# 메인퀘스트1

나만의 헬스도감 만들고 배포하기

**서비스 주소: https://ai-agent-mainquest1-health.vercel.app**

헬스 입문자가 헬스장에서 폰으로 기구별 운동 자세·자극 부위를 바로 확인하고, 운동하고 싶은 부위에 맞는 기구를 찾아볼 수 있는 모바일 웹 도감입니다. 자세한 기획은 [PRD.md](PRD.md)를 참고하세요.

## 주요 기능

- **기구로 찾기:** 기구 20개 목록, 이름 검색, 부위 필터
- **부위로 찾기:** 앞·뒤 인체 그림에서 근육을 눌러 맞는 기구 찾기
- **기구 상세:** 운동 자세(단계별), 자극 부위(주동근·보조근), 주의사항. 가슴 기구 3개는 기구 사진과 단계별 자세 그림 포함
- **로그인 / 회원가입:** 이메일 + 비밀번호 (Supabase Auth)
- **즐겨찾기 / 운동 기록:** 로그인 전에는 이 기기의 `localStorage`, 로그인 후에는 Supabase에 저장 (RLS로 본인 데이터만 접근)

## 기술 스택

Next.js (App Router) · TypeScript · Tailwind CSS · Supabase · Vercel

## 실행

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다.

로그인 기능을 쓰려면 `.env.example`을 `.env.local`로 복사해 Supabase 값을 채우고, `supabase/migrations/`의 SQL을 Supabase SQL Editor에서 실행합니다. 환경변수가 없으면 로그인 없이 이 기기 저장 모드로 동작합니다.

## 폴더 구조

```
app/                 화면 (홈, 기구 목록·상세, 부위로 찾기, 즐겨찾기, 운동 기록)
components/          공통 컴포넌트 (인체 그림 BodyMap, 기구 카드 등)
data/                목업 데이터 (기구 20개, 부위 분류)
lib/storage/         즐겨찾기·운동 기록 저장소 (로그인 전 localStorage, 로그인 후 Supabase)
lib/supabase/        Supabase 클라이언트
public/images/       기구 사진과 운동 자세 그림
supabase/migrations/ DB 스키마와 RLS 정책 SQL
.claude/skills/      Claude Code 스킬 (기구 추가, DB 변경 절차)
CLAUDE.md            Claude Code 규칙 파일
```

## 회고

### 진행 과정

| 단계 | 한 일 |
|---|---|
| 기획 | Claude Code와 인터뷰하며 서비스 목적, 핵심 화면, 기능, 개발 경험, 일정을 하나씩 정하고 PRD로 정리했다. 정하지 못한 항목은 [미정]으로 따로 표시했다 |
| 범위 정하기 | 하루 안에 배포해야 해서 "목업 데이터로 구현할 것"과 "나중에 백엔드가 필요한 것"을 나눴다 |
| 화면 구현 | 기구 20개 데이터, 검색·부위 필터, 직접 그린 SVG 인체 그림, 즐겨찾기·운동 기록(`localStorage`)을 먼저 만들었다 |
| 백엔드 | DB 구조와 RLS 정책을 먼저 설계한 뒤 Supabase로 이메일 로그인과 데이터 저장을 붙였다. 로그인 전 데이터는 첫 로그인 때 계정으로 옮긴다 |
| 보안 검증 | 비로그인 접근, 다른 계정 데이터 조회·수정·삭제, 다른 사람 이름으로 추가, 잘못된 값 입력을 직접 시도해 모두 막히는 것을 확인했다 |
| 마무리 | 가슴 기구 3개에 사진을 넣고, 규칙 파일·MCP·스킬을 추가한 뒤 Vercel에 배포했다 |

### 잘한 점

- **PRD를 먼저 썼다.** 요구사항마다 "확인할 조건"을 적어 두어서, 구현이 끝났는지 판단하기 쉬웠다. "레그를 검색하면 3개만 나와야 한다"처럼 구체적으로 적은 조건이 테스트 기준이 됐다.
- **목업 → 백엔드 순서로 나눴다.** 화면을 먼저 완성해 확인한 뒤 저장소만 바꿔 끼웠다. 저장소 코드를 `lib/storage/`에 모아 둔 덕분에 화면 코드는 거의 고치지 않았다.
- **RLS를 "화면에서 안 보인다"로 끝내지 않았다.** 두 번째 계정의 세션으로 다른 사람 데이터를 직접 수정·삭제하는 요청을 보내 0건이 바뀌는 것까지 확인했다.
- **민감 정보를 분리했다.** 키는 환경변수로만 관리하고, 배포된 코드에 공개 키만 들어 있는지 직접 열어 확인했다.

### 어려웠던 점과 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| Next.js 16에서 경고가 났다 | 버전이 바뀌면서 주소 값(`params`)을 읽는 규칙이 달라졌다 | 설치된 Next.js 문서를 먼저 읽게 하고, 해당 부분을 `Suspense`로 감쌌다 |
| SQL을 다시 실행하니 `already exists` 오류가 났다 | 첫 실행에서 이미 테이블이 만들어졌고, 에디터에 남은 SQL이 함께 실행됐다 | 새 쿼리 탭에서 확인용 SQL만 실행했다. 이 내용을 스킬에도 적어 두었다 |
| 가입했는데 로그인이 안 된 것처럼 보였다 | 평소 쓰는 브라우저에서 가입해서, 테스트하던 브라우저와 세션이 달랐다 | 서버 로그로 원인을 찾고, 두 브라우저를 "두 기기"로 활용해 기기 간 동기화까지 확인했다 |
| 무료 이미지 사이트에 맞는 기구 사진이 없었다 | 대부분 사람이 운동하는 사진이고, 펙덱은 검색 결과가 0건이었다 | 사진을 직접 준비하고, 사진이 없는 기구는 인체 그림으로 대신 보여주게 했다 |
| Supabase 설정 화면을 찾기 어려웠다 | 대시보드 메뉴 구성이 문서와 달랐다 | 주소창의 프로젝트 ID로 URL을 만들고, 메뉴 위치를 하나씩 확인했다 |

### 배운 점

- AI와 함께 개발할 때도 **무엇을 만들지 먼저 글로 정리하는 것**이 가장 중요했다. 한 번에 하나씩 질문받으며 정하니 놓치는 부분이 적었다.
- 공개 키(publishable key)는 브라우저에 노출되어도 되고, **실제 데이터 보호는 RLS가 담당**한다는 구조를 이해했다.
- 규칙 파일(`CLAUDE.md`)과 스킬로 **반복되는 절차를 문서로 남기면** 다음 작업에서도 같은 품질을 유지할 수 있다.
